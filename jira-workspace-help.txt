JIRA LOCAL WORKSPACE - Jira timer

This project contains only the standalone Tampermonkey Jira work log timer.
See README.md for the project overview.

Installation and updates:
1. Open the EXISTING Jira timer in Tampermonkey (create one on first install).
2. Replace its entire contents with jira-workspace-timer.user.js and save.
3. Allow Tampermonkey access to https://jira.alza.cz and userscript execution.
4. Refresh Jira. The timer appears at bottom left.
5. Do not install a second copy or clear site data when updating.

The script has @updateURL and @downloadURL pointing to main. Tampermonkey
requires a publicly published file and a higher @version than the installed
copy. For a release update both @version and VERSION. Configure update checks
under Tampermonkey -> Dashboard -> Settings -> Script Update. Never put a
token in the script or URL.

Usage:
- Stop other timers, including Clockify, before starting. This timer does not
  control Clockify.
- START tracks the open issue. If another issue is running, it is saved first
  and the new timer starts when the previous one ended.
- Navigation alone does not switch timers.
- STOP saves the tracked issue. CANCEL discards the unsaved timer without a write.
- ADD MINUTES logs positive whole minutes to the open issue using the button or
  Enter. After success the field is cleared. Zero or blank (including favorite
  +min) logs nothing and shows the "Added 0 minutes" toast.
- On /browse/<KEY>, the URL always identifies the target; selectedIssue applies
  only on boards and backlogs.
- The auto button opens automatic work logging settings. When enabled, creating
  an issue through this Jira page logs the configured minutes (default 10),
  including Sub-task Bugs via Jira forms and REST. A valid returned key is
  required. It is off by default, does not affect a running timer, and cannot
  observe creation outside this page. An uncertain result is not retried;
  use Process pending entries to verify its marker. Green auto with a filled
  dot means enabled (minutes in tooltip); gray hollow dot means off; red auto !
  means corrupted settings.
- The favorites N chip opens up to 10 favorites; the close button closes it.
  Each displays its title, project name and key. +min logs to that issue (quick
  choices 15/30/60 only prefill; Save or Enter submits). The green button starts
  a timer even on a different issue and closes the list; the red button stops a
  running favorite. The menu edits its local name and emoji, restores the
  original, removes it, or retries a failed project name lookup. Removing a
  favorite does not alter work logs. + opens search: clicking a result opens a
  new tab; only its + adds it. The search close button closes only search.
  At the limit, remove a favorite before searching again.
- Manual entries do not change a running timer. Intervals can overlap; log only
  time not already recorded.
- Beneath the clock, the open issue shows only the signed-in user's time,
  rounded to tenths of an hour. Colleagues' work logs are excluded. When exact
  totals differ, parentheses show the personal total including subtasks, e.g.
  2h (3.5h). Identity, author and loading errors appear instead of a partial
  or zero total.
- The panel is 240px wide and adapts to narrow screens. Green means tracking
  the open issue, blue another issue, and red idle.
- Save and discard confirmations are separate temporary cards above the panel.
- The legacy Clockify section is hidden without leaving a gap. This does not
  uninstall it on the server or stop any running Clockify timers.

Logged time:
- Work logs go directly to Jira, not Clockify; do not log the same time twice.
- The remaining estimate is preserved.
- The minimum work log is one minute. For a shorter timer, the comment
  explains the actual duration and the increase to the minimum.
- Durations longer than one minute are rounded down to whole minutes.

Persistence, errors and recovery:
- Timer and save state use localStorage on jira.alza.cz, shared between tabs
  of the same profile, not between profiles or devices.
- AUTO settings and its queue are separate from timer state; do not delete
  their entries while work logs remain unverified.
- Favorites are stored separately and shared between tabs. A corrupted list
  is never overwritten; the chip shows ! and the error appears when opened.
- Do not clear site data or switch Jira users during unfinished work.
- API errors remain visible. An uncertain POST is not repeated automatically.
- Save / Verify looks for the unique marker on your own work log, never
  another author's. A found entry is confirmed without duplication. If not
  found, inspect Jira Work log manually before sending the same time again.
- A failed switch preserves both the original issue and intended destination.
- After an independent manual entry fails, the timer continues but other
  actions wait until the unfinished entry is resolved.
- Jira session cookies are used; no API key or Clockify account is needed.

Validation:
- node --check .\jira-workspace-timer.user.js
- node .\jira-workspace-timer.test.cjs
- npm test (full local regression suite, including Chromium and screenshots)

Tests use mocks, never live Jira responses or real work logs.
